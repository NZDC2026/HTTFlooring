# 供应商金额/税额贷项与采购差异（030）

仅修改 htt-backend；澳洲 AUD、公司时区及既有 CASH/NON_CASH GST 规则继续适用。未执行正式账套迁移。

## 操作入口

- `POST /api/v1/supplier-bills/{id}/amount-credits`：`reference`、`reason`、`lines[{billLineId,net,tax,description}]`。适用于收货匹配账单与独立费用账单；不要求采购退货，不改变实物数量。净额与税额可分别调整；合计必须大于零，分别不得超过原账单行尚未贷记的净额和税额。不提供脱离原账单的任意会计贷项。
- `POST /api/v1/supplier-bills/with-variance`：`{bill:原SupplierBillInput,reason}`。数量仍匹配原收货，明确接受实际票面净额/税额。原 `/supplier-bills` 继续要求精确匹配，不能静默接受价差。
- 原供应商付款、预付核销、贷项跨账单抵扣/解除、退款及更正接口继续使用。金额贷项生成原有供应商贷项余额来源；现金制进项 GST 按有效支付、贷项可退款余额与退款状态重算。

金额贷项需 `purchase.credits.adjust`，差异账单需 `purchase.bills.variance.post`；默认仅 ADMIN/FINANCE，叠加原读写权限。所有写操作必须使用 Idempotency-Key，错误不产生余额、凭证或库存残留。

## 成本口径

按用户确认：在库部分调整库存价值，已售部分计采购价差。差额为实际非可抵扣成本减去原匹配 GRNI；可抵扣进项 GST 独立记账。原 GRNI 按收货冻结成本清零，AP 按真实账单入账。

采用现有 SKU/仓库移动平均成本池：在库份额 `min(当前onHand / 本次匹配基础数量,1)`，保留两位金额尾差；负向调整以当前库存价值为下限，剩余进入采购价差。该份额不是序列号或原采购批次逐件追溯。新账单采购价差默认 5120；非库存采购使用原收货费用账户。贷项对库存价值执行相同分摊；独立费用贷项冲回原费用账户。

`inventory.purchase_value_adjustments` 保存数量基数、库存/费用分摊、过账账户及调整前数量/价值。延迟约束核对来源和对应 GL；对账查询包含这些纯价值事件。物理退货与后续剩余金额贷项保持独立，额外清算差异明确进入采购价差，避免重复降成本或留下清算余额。

## 边界

运费/landed cost 分摊、验收前独立税票、脱离来源的纯价值减值、历史已关闭期的重新估值不在该入口内。批次货位是实物维度，未改变移动平均估值方法。生产 GST/BAS 核验与历史数据迁移仍需上线验收。
