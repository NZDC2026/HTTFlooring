# 客户独立净额/税额贷项

029仅改htt-backend。澳洲/AUD/公司营业日口径；001—028保持不变，三个客户端未改，正式库未迁移。

## 范围与上限

关联已过账原发票行，逐行显式输入net和tax，不按退货数量或当前税率自动推算。允许纯净额折让、纯税额冲减及不同比例的净额/税额组合；两者均须非负、最多两位小数，行gross必须为正。调整不得超过该原行尚未冲减的净额或税额；金额贷项和原数量贷项共同消耗这些上限。原FRE/无税行不能产生原本不存在的可冲减税额。

AMOUNT类型没有quantity、returnLineId，不要求收到实物退货，也不接收数量/退货参数。适用于价格折让和原税额纠正，不执行库存收回或成本冲销。真正退货继续走仓库原流程；之后的QUANTITY贷项按原累计数量计算，并以剩余净额/税额封顶，不重复冲减先前金额折让。全部货款已金额冲减后，可依法记录剩余退货数量的零金额数量贷项。

原发票、税率/代码、数量、实际收款、预收、核销、贷项和退款均保持不可变。新金额贷项使用正式CN编号、独立审计和Outbox，保留描述、原金额、原税额/税码、原GST口径、调整前可用额度和商品类型快照。

本批为减少原收费的贷项，不提供超原额、无来源贷项、负数贷项/借项补收、变更原发票税码或实际银行操作；需要增加收费时不能用负数贷项绕过原销售开票流程。

## API

POST /api/v1/sales-invoices/{id}/amount-credit-notes

员工JWT、公司上下文和Idempotency-Key必需，成功201。需sales.credits.adjust、sales.credits.write、sales.credits.read、sales.invoices.read及原客户范围。新增adjust权限默认仅ADMIN/FINANCE；旧OFFICE数量贷项权限不包含金额/税额自由调整。旧销售角色重复初始化显式排除新财务权限。

```json
{
  "reason":"Approved price and GST correction",
  "lines":[
    {
      "invoiceLineId":"<original invoice line UUID>",
      "net":20.00,
      "tax":3.00,
      "description":"Verified adjustment against original invoice"
    }
  ]
}
```

支持1—50条不同原发票行，同一原发票，按ID排序规范化。reason为1—2000字，description为1—500字，trim后处理；net/tax显式输入。返回沿用sales-credit-notes详情，增加creditType=AMOUNT；金额行quantity和returnLineId为null，包含creditType和description。原QUANTITY接口保持，不能通过发送额外net/tax控制其权威金额。

GET /sales-invoices/{id}/creditable增加creditableNet和creditableTax，数量可冲减值继续独立反映真实数量；金额折让不虚增已退货数量。金额和数量详情/列表可区分creditType。所有余额、可抵和可退查询保持原接口。

## AR、信用与分录

贷原发票AR并带原party，按net借原收入、按tax借原Output GST，当前映射更改后仍沿用原科目。应收及客户信用投影减少同额gross；不重新释放原订单未开票承诺，不恢复库存预留，不虚构收款。

未付款原发票的折让只减少应收，不能变成可提现现金。已收/已核销的金额按当前净结算形成真实可抵/可退余额；客户总净信用、其他订单资金保护和贷项/退款共用容量继续生效。对其他发票抵扣/解除不重复释放客户总额度。

## GST

NON_CASH按原发票冻结口径，当日追加明确tax的负向归属；不重新计原税，也不使用公司当前税率覆盖来源。

CASH按该原发票行调整后的剩余gross/tax、有效净结算及已归属税余额累计重算差额。净结算仍覆盖可退余款时，继续遵循现有发票级累计归属；后续实际退款、抵扣/解除、收款撤销和预收解除按当前余额重算，不能按当前税率推算或简单取反历史税。只调净额也可能改变部分收款的现金制税务比例；只调税不要求虚构退货。

已核销预收形成贷项可正常退款；金额调整发生在预收核销前时，核销使用剩余真实账单金额/税额，并清算原预收税份额。受金额调整影响的核销归属当前核销日，避免回写已关闭的原收款期间；原收款及税记录保留。未用预收仍可按原规则退款，不能与贷项退款重复消费同一资金。

## 权限、事务与并发

API在幂等缓存前验证权限及原客户范围，SQL再次校验有效成员和客户。订单、来源发票、客户/信用按固定顺序加锁，与原收款、核销、贷项抵扣、退款及归档边界串行校验。原发票不可见时需先恢复可见性；金额调整不会重开订单或恢复已冲销单据。

同键并发仅产生一个CN、凭证、审计和Outbox，改变金额/税额同键冲突；不同键按当前剩余净额和税额检查容量。多行及其编号、AR/GST、信用、审计/Outbox与成功幂等结果同事务，任一行无效或审计失败全部回滚，可原键重试。

旧QUANTITY行默认类型及数量保持不变，新AMOUNT快照不可变；公司复合FK、RLS和现有append-only保护保留。新增延迟校验来源/类型、净额/税额/数量上限、原快照、逐账户party精确分录及有效结算/GST余额。

库存/成本、AR/AP、预收预付、GRNI与GL继续使用原一致性检查；本批不是银行对账或完整BAS。阶段B其他欠交仍见原验收清单。
