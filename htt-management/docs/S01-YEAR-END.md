# S01 年度损益结转留存收益

更新：2026-10-23。本阶段完成本地年度损益结转、年结锁、受控撤销、自动备份及报表处理。原有期间关闭仍是独立的日期锁；年结不代表完成税务申报或工资申报。

## 使用流程

入口 `/accounting/year-end`，可从 Accounting periods 的 Financial year-end 链接或管理页面目录进入。

1. 按公司设置的财年结束日准备一个完整财年，完成调整及原有对账工作。期间必须无缺口、无跨财年边界，覆盖整年并全部关闭。
2. 运行年结预检。复用原有期间检查：财年已结束、未完成审批/过账、未解决恢复任务、银行对账、AR/AP、存货、预收预付等异常必须先处理。以前年度未结转的损益余额也会拦截，不能直接漏过旧利润。
3. 核对每个收入/费用科目及留存收益的拟结转金额，填写理由并明确确认。提交时再次检查数据摘要和全部业务校验，旧预检不能绕过新变化。
4. 程序先在当前档案的 `year-end-backups` 下写入并回读验证完整业务备份，记录文件名及 SHA-256，随后以财年最后一天生成独立 `YEAR_END_CLOSE` 分录。正常日常过账仍受期间锁约束；只有主进程年结服务在同步、限定日期的内部作用域中可写入该结转分录。
5. 年结后，可继续在开放的新年度期间记账。若需修改已结财年，先撤销最新年结，再单独反关账对应期间，完成调整后依次关账并重新年结。旧结转、撤销、原因、操作者、备份证据全部保留。

## 金额与报表规则

- 使用整数分归集收入/费用的借贷余额。将各个非零损益科目结为零；净利润贷记留存收益，净亏损借记留存收益。留存收益必须为唯一有效的系统权益科目；有余额的损益科目须有效。
- 净利润为零但仍有收入/费用余额时，仍结清各损益科目；整年所有损益余额均为零时，只记录年结及备份，不制造零值分录。
- 总账及试算表包含结转和撤销。次年损益期初余额归零，历史交易不删除。
- 损益表统一排除 `YEAR_END_CLOSE` 类型，包括同类型的年结撤销分录，防止历史收入/费用被结转冲为零；Dashboard、保存报表和报告包使用相同损益计算器。
- 资产负债表继续根据完整总账计算。结转只在累计损益与留存收益间重分类，不改变总权益，也不重复计利润。撤销年结按原年末日生成反向结转，恢复原累计损益；未来年度交易保留。
- 日后在开放期间冲销旧交易是允许的：旧分录的状态/反向链接更新不改变已结财年的原始金额。年结保护原始 GL 日期、账户、金额、来源等不可变证据，而不是冻结所有生命周期元数据。新增本期反向分录进入本期损益。

## 控制与恢复

预检和阅读使用 `accounting.read`；结转使用 `accounting.periods`，撤销使用 `accounting.reopen`。ADMIN/FINANCE_ADMIN 可操作，ACCOUNTANT/AUDITOR 只读，其他无会计读取权限角色不可访问。操作者来自可信主进程会话，拒绝伪造 actor 字段、缺少确认和过短理由。

若结转涉及的普通损益科目已被停用，撤销前须先恢复其有效状态。

同一 operation ID 和相同输入可安全查回既有结果；相同 ID 的不同输入拒绝。一个财年不能重复或交叉结转；存在已结的更晚年度时不能先撤销早年。多次重结会产生新的记录，原始记录保持 REOPENED。

业务命令原子保存结转记录、分录、缓存及幂等回执。检查或分录失败回滚到原状态；备份失败不会生成结转。若磁盘提交确认失败，沿用现有主进程阻断及重启审计恢复。年结不会自动发送、支付或连接后台。

每次业务命令都在保存前维护已结财年的完整性：不能经普通期间反关账绕过年结，也不能改动旧日期/金额、删除结转来源或改变已冻结账户分类。反向分录、来源摘要、逐行金额、全部期间覆盖、生命周期及操作回执在备份恢复时重新验证。科目重命名不重写已冻结报表。

结构版本升为 **32**：旧版本迁移为一个空 `yearEnds` 仓库，保留原始账务并保存迁移前备份，不猜测或补造年结。当前版本缺少仓库或含不匹配年结证据的备份会被拒绝；带年结证据却降称旧版本同样拒绝。完整业务备份包含年结记录；外部服务日志仍按 E01–E03 的原规则独立保存。

本轮支持配置中的完整常规财年；短财年、改变财年结束月造成的过渡期间、合并账和外币重估不是 S01 自动计算范围。对这些情况应先另行定义调整规则，不能通过不完整日期范围绕过预检。

## 验证记录

实际项目 `pnpm build` 通过；最终 `pnpm test:ci` **170 个文件、3742 项通过**（261.42 秒）。28 项直接覆盖年结，另有 3 项生产模式仓库归属测试。67 份文档和 149 个表格表面的索引检查通过。

原生隔离档案完成预检、实际结转/分录明细、普通期间反关账拦截、受控撤销、重载持久化与 AUDITOR 只读操作。记录的结转及撤销备份均通过 SHA-256 比对，原交易未改动。原生首轮发现并修复了共享仓库提前加载导致主进程误用渲染器通道的问题；修复后完整流程通过。
