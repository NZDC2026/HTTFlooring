# Bank reconciliation evidence for period close

Period close no longer accepts a saved COMPLETED/difference-zero label as proof by itself. A shared read-only verifier recalculates the relevant bank reconciliation chain from dated GL, bank opening balances and incremental cleared row identities. It checks unique identities, valid statement sequence/dates, whole-cent balances, source row existence and financial lifecycle, repeated clearing, exact saved book/outstanding/adjusted/difference totals, and processed imported statement amounts/matches/clearing. Internal duplicate-correction offsets remain in GL/registers and cannot be cleared as external bank activity.

For each bank, close preflight checks all earlier statements plus the earliest statement covering the period end. A valid later covering statement remains supported. Missing bank ownership and invalid evidence produce BANK_RECONCILIATION_INVALID with a banking-workbench link. Existing unmatched/stale/uncleared imported-line checks and the requirement for bank coverage remain in force. Close reruns the same preflight before changing period state. It does not rewrite any saved reconciliation, journal or clearing ID.

Creating a subsequent bank reconciliation now verifies its preceding chain before extending it. The candidate list and main command use the same financial-date lifecycle rule: a currently REVERSED original is not eligible at/after its reversal date. A prior statement remains valid when the original has a unique exact opposite linked reversal on a later financial date. The original and offset identities, account/amount pairing and lifecycle must agree; missing, ambiguous, malformed or wrong-date reversal evidence cannot make an earlier row count as POSTED. This preserves legitimate earlier clearing while refusing newly selected reversed or internal-offset rows. A subsequent statement can clear the later reversal as before.

Interrupted reconciliation recovery uses this shared verifier, while retaining its own durable result binding, saved request, independent reviewer/approver and revision checks. No schema change, backend connection, automatic reconciliation rewrite or automatic reopening is introduced.

Regression coverage includes close/reopen/restart with unchanged GL/clearing, every saved monetary component, missing/unknown/repeated rows, status corruption, earlier-chain corruption masked by a later zero label, covering statements after period end, reversed-row rejection and command rollback, later valid reversals, exact reversal pair corruption, and existing recovery/duplicate-repair flows.
