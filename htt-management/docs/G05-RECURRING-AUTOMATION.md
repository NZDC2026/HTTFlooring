# G05 周期业务本地自动执行

完成日期：2026-10-22（Pacific/Auckland）。保留现有主进程、Repository／Service、Mock、持久化、备份及审计架构，不增加独立后台。

## 支持范围

周期发票、费用账单和银行交易模板均可生成待审核草稿。发票／费用沿用现有来源快照、取价、税务重算及正常审核／过账流程。新增银行模板保存银行、方向、整分金额、手工对方科目、说明、参考及周期；生成的是本地银行录入草稿，不冒充银行导入流水或实际付款指令。

银行草稿须人工审核并批准后，再由具备 banking.write 和 accounting.post 的用户明确过账，调用现有银行交易服务、财务写入门禁、会计期间和原子提交保护。自动扫描绝不批准或过账。银行／银行 GL／对方科目在生成、批准和过账时重新验证；控制科目、银行间转账及失效账户不能借模板绕过正常来源业务。过账后结果保留正常银行登记与分录冲销流程。

## 桌面调度与停机补跑

- 三种业务类型默认全部关闭，必须分别明确启用；启用、关闭和生成均按可信当前用户的既有业务权限校验。
- 桌面主进程每分钟扫描，并在成功 bootstrap／重新登录后补扫。用户登出、应用退出或无相应权限时不生成，不借用模板创建人的旧权限。ACCOUNTANT 仅执行其有权的发票类型；PURCHASING 仅执行其有权的费用类型。
- 以公司时区计算业务今天。仅执行 Active、已到期且未超过包含式结束日的下一期，按原发生日期、类型及 schedule ID 确定顺序；不把积压业务改成今天或跳过旧日期。
- 每轮最多尝试 20 个发生项，剩余积压在后续分钟／手动扫描继续。界面中的剩余数量是仍到期的计划数，不是精确积压发生项数。暂停或已结束计划不执行。
- 月／季保持原始月日锚点，短月夹至月末；费用沿用原付款天数与日期参考后缀。银行周期沿用同一日期函数。
- 桌面操作 busy 时跳过计时轮次，主机另有扫描重入保护；每期独立原子提交。发生需要重启的提交错误后停止计时写入，不无限重试。

本地调度依赖应用运行及有效登录，不是关机后继续工作的系统服务。操作系统休眠结束后恢复计时，下次扫描按同样规则补跑。页面提供 Refresh automation status 和 Scan enabled types now；计时器产生的新状态在刷新或下一次主进程同步后显示。

## 错误队列和幂等

一个发生项失败时，完整回滚该期新草稿及计划推进，再由主进程生成可信失败凭据；保存计划、日期、错误、尝试次数、操作者、时间及历史。renderer 不能伪造错误入队。该计划后续发生日被阻止，其他计划继续；失败项不自动重试。

用户修正客户／产品／账户等错误，必要时恢复计划，再填写原因并 Authorize retry。下一次已启用类型扫描重试相同发生项。再次失败只累计一次尝试；成功追加 RESOLVED 并链接原生成草稿。也可通过原单期流程生成，再在队列确认已解决，保留完整历史。禁用的业务类型不会因授权重试而自动启用。

发票／费用继续使用 `recurring:<scheduleId>:<date>` 创建请求，银行发生项以 schedule/date 唯一。重试不再生成已存在的发生项，取消的生成草稿仍占有原发生日。银行过账使用确定性银行操作 ID，保留批准、过账、取消的可信审计历史与结果 ID。提交前失败保留原发生日；持久化结果无法确认时阻止写入，重启后以已提交状态为准，不重复生成或入账。

## 页面、权限及恢复

`/automation/recurring` 保留原发票／费用计划列表与详情，并加入类型启停、本地扫描、错误历史／重试、银行模板、银行草稿审核／过账。银行新模板表单折叠显示。AUDITOR 只能读取；无相应类型读取权限的数据从主进程视图剔除。按钮限制之外，所有动作都有独立可信授权和严格参数验证。renderer 无法指定扫描今天、操作者或超出上限。

快照升级至 schema 26，新增 recurringBank（schedules/drafts）与 recurringAutomation（policies/tasks）。版本 25 及以前的合法备份迁移时以空表、自动生成关闭初始化新功能，保留已有计划、财务数据及迁移前备份。包含新自动化证据的数据不能标成旧结构版本。正常备份包含模板、策略、队列、生成草稿与审核历史；恢复验证周期完整性、唯一发生项、错误历史状态机、账户与过账结果绑定。完整档案恢复须沿用 Data protection 的预览、恢复、重启流程，不进行无证据重放。
