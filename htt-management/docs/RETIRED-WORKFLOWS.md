# 已确认停用的六类工作流

更新：2026-11-01。用户确认清除在线收款、电子付款/ABA、付款通知、银行直接支出、银行转账、手工凭证入口，并要求保留原始代码以便将来恢复。

实现采用统一编译配置 `src/features/security/optionalWorkflows.ts`。六个开关均为 false，没有提供运行时设置或渲染器开启通道。原服务、仓库、页面实现、数据模型及历史数据保留；没有删除业务流水，没有回滚历史分录，也没有更改数据库版本（仍为 33）。阶段开始的完整源码摘要及被修改文件原件另存于开发工作区 `baselines/remove-unwanted-start`，不写入业务档案。

## 当前行为

| 已停用 | 页面与可信主进程处理 |
|---|---|
| 在线收款 | 隐藏 Stripe 配置、创建支付链接、打开链接和在线收款确认；生产服务拒绝重新启用及创建。旧 checkout 工作冻结，不查询提供方、不自动入账，日志仍保存在原档案。邮件和发票催款保留。 |
| 电子付款/ABA | 页面目录及各处快捷链接移除；旧付款批次与 ABA 页面不能通过旧路径打开操作；桌面命令拒绝准备、审批、导出、执行等入口。原批次、银行信息、审批及旧文件证据不删除。 |
| 付款通知 | 采购输出只显示采购单；付款详情不再链接通知单，邮件准备不提供付款通知。旧通知版本保留，旧待发送通知不再处理。 |
| 银行直接支出 | 手工银行录入仅保留 Money In；Money Out 的桌面命令被拒绝。周期银行录入入口与生成任务同步停用，以免从该路径重新产生直接支出。采购账单付款、工资付款登记、客户退款等源业务保留。 |
| 银行转账 | 移除按钮，旧新建转账路径显示停用提示，桌面 createTransfer 命令拒绝。已有转账分录保留。 |
| 手工凭证 | 隐藏 New Journal，旧新建路径显示停用提示，桌面直接 journals.post 拒绝。总账、凭证登记簿、历史明细、受控冲销以及销售/采购/工资/年结自动生成分录保留。 |

应用启动时，可信主进程对 BusinessHost 和 ExternalServices 安装范围限制，后台扫描也使用该限制；不是仅用 CSS 隐藏按钮。保留的通用服务及历史回归夹具继续验证原来的底层逻辑，新增生产范围用例验证限制已安装时的行为。
