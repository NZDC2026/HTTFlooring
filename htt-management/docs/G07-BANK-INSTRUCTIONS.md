# G07 银行指令文件与工资批次

范围：CommBank／CommBiz 为默认及优先验收配置，保留 NAB Connect 自平衡 ABA 选项。沿用本地可信主进程、Repository、原子持久化及审计，不连接独立后台，不上传银行文件、不执行付款，也不声称已获银行认证。

## 业务流程

入口 `/banking/instruction-files`，也可从 Supplier batches、Payroll 和页面目录进入。付款银行须为活跃 AUD 银行及资产 GL。银行提供的 Direct Entry ID、实际 BSB、账号、账户名、remitter 与描述必须人工复核保存；账簿中的掩码不能用于生成文件。供应商与员工的结构化银行资料单独版本化，旧 free-text 字段不自动猜测。主数据版本变化后须重新复核。

供应商来源为已批准、尚未过账的付款批次；按供应商汇总实际分配金额。工资来源为已过账澳大利亚工资单，按员工净工资生成 code 53。仅支持整批尚未支付的净工资；已有部分净工资付款时阻止生成，必须先核对原付款归属。PAYG、super 等负债沿用独立付款流程，不混入净工资文件。

Preview 无持久化或分录副作用。Prepare 保存不可变付款金额、受益人、银行资料版本、源摘要、完整文件、SHA-256 和操作者证据。另一名具有相应权限的用户批准；创建者不能自批。批准、首次导出及重新导出再次验证当前来源和银行资料，过时快照须显式作废并重新准备。

导出要求明确确认重复上传风险；重新导出保留相同文件字节和 SHA，每次新操作追加审计。导出只改变本地签发状态，不生成收付款或分录。相同 operationId、操作者和请求跨重启返回原结果；不同数据或用户不得复用操作 ID。

已下载文件的副本不会因本地 Void 消失。作废必须确认外部未执行或已取消，保留历史。人工独立核实银行执行并填写外部参考号后，才允许 Record verified result locally：供应商走原批次过账，工资走原净工资负债付款；原有金额、期间、财务门禁和对账保护保持有效。后续银行资料更新不会篡改已签发文件，也不会阻止按原财务证据登记已经发生的付款。

准备至导出期间预留来源与供应商账单，阻止绕过指令直接付款或重复预留。记录完成后释放账单的剩余欠款供后续付款。指令拥有的本地付款只能通过指令正常冲销；供应商使用原付款日，工资可指定合法冲销日。Reverse local payments 只撤销本地账务，保留文件与外部参考号，不撤销银行付款。已完成对账或关账仍阻止不合法冲销。

## 文件约束与依据

实现采用官方字段位置：[CommBank Direct Entry file specification](https://docs.commbank.com.au/sftp/direct-entry/file-spec)（版本 7，2026-08-01）和 [NAB Connect Direct Entry guide](https://www.nab.com.au/content/dam/nab/documents/guides/banking/nab-connect-australian-direct-entry-payments-and-dishonour-report.pdf)。

每条记录为 120 ASCII 字节，CRLF 换行且最后一行保留 CRLF，无 BOM。顺序为 header 0、供应商 credit 50／工资 credit 53、强制 contra debit 13、trailer 7。Debit 等于 credit，net 为零，detail count 包含 contra。金额使用整数分及零填充；BSB 为 nnn-nnn，账号保留前导零并右对齐。

支持的保守子集为 1–9 位非零数字账号、受限 ASCII 文本、2000–2099 年及最多 500 个受益人；单行／总额不能超出十位分金额。超长字段、非支持字符、小数分、同付款账号、重复受益人及溢出拒绝，不静默截断或转写。CBA 提交日期窗口为业务日期前 4 天至后 419 天，NAB 为前 7 天至后 90 天，边界包含。银行截止时间、假日处理、账户所有权、银行开户授权及银行实际接受结果必须在银行渠道另行确认；当前没有银行端上传或联网验证。

## 权限、恢复及验证

主进程独立检查 banking.read/write、供应商采购付款权限或 payroll.read/post/approve/manage。ACCOUNTANT／AUDITOR 不具有银行写权限；没有 payroll.read 的银行读取角色不会收到员工银行资料、工资指令或工资请求结果。独立审批还要求 accounting.post。UI 控件同步按角色限制，不能代替主进程授权。

持久化结构升级至 28；合法旧版本迁移为空银行指令表，保留迁移前备份。恢复验证银行／受益人引用和版本序列、文件重建与 SHA、源摘要、工资及供应商金额、审批历史、付款绑定、预留冲突、请求指纹与历史结果。非空新结构不能冒充旧 schema。主机命令覆盖整笔付款和指令状态：中途失败回滚；持久化确认不确定时停止新写入，重启后凭同一请求恢复已提交结果。

自动测试覆盖独立解析的文件字段、金额／日期边界、前导零、contra 和 trailer，供应商与工资真实主进程链路，独立审批、来源变化、重复导出、作废、剩余欠款、角色隔离、原子回滚、关账阻止、冲销、重启重试、旧版本迁移及损坏备份拒绝。实际项目完整回归：136 个测试文件、1793 项测试全部通过，0 失败，219.29 秒。新增 20 项 ABA 格式／边界用例、28 项主进程集成用例及 2 项路由／角色覆盖；最后强化重复来源备份校验和日期／入口标签后，在实际项目重跑银行指令及页面 179 项全部通过（21.30 秒）。最终 TypeScript、Vite renderer 及 Electron main/preload 生产构建通过；既有大分块提示仍为警告。

执行命令：`tsc -b && vite build`；`node --no-maglev ./node_modules/vitest/vitest.mjs run --pool=forks --maxWorkers=2 --execArgv=--no-maglev`。沿用 Node 24 已验证的 no-maglev 测试配置。
