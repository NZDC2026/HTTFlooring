# S02–S04 本地业务扩展

更新：2026-10-23。范围是本地可信主进程、现有库存/工资/客户仓库与完整业务备份；不新增后台，不发送申报或付款。

## S02 澳大利亚复杂工资

在创建或重算 pay run 的员工区选择 Configure complex payroll，填写计算来源。系统保存参数、来源及员工/工资项快照，沿用草稿、批准、过账、付款登记与冲销主链。

- 特殊扣税：Reviewed exception 要求员工使用 Manual PAYG、填写异常计算依据，并输入经外部复核的总扣税。不会将 HELP、奖金、ETP 或未休假税自动套入标准周薪表。
- Award/penalty：按已批准的小时制 timesheet 配置规则名、协议/等级/有效费率依据和倍率。倍率作用于该行原费率；同一工时不能重复应用或叠加。跨班次、公众假日和不同费率时段需先拆工时；薪资制额外收入继续使用明示调整。
- 休假累计：按已审核的本期普通工时 × 年度 entitlement weeks ÷ 52 计算，保留四位小数。普通工时、年度周数及适用资格由用户确认；不会从岗位名称猜测 casual、shiftworker 或 Award 待遇。
- 离职结算：必须匹配员工档案的 end date，并处于本次工资期，付款日不得早于离职日。必须使用异常人工扣税和 reviewed SG。年假需精确支付已记录余额，加本期累计、减本期已用；支持审核后时薪、leave loading，以及独立的 Notice、Redundancy、Long service leave、ETP、Other 固定收入组件。个人病假不会自动支付。
- 最终工资过账扣减年假，冲销恢复；有最终工资的员工不能再建普通工资；修改此前已过账工资必须先冲销后续最终工资。任何后续工资会在最终工资建成后被拦截，避免重复结算。
- 工资单列出行来源；审批页及导出保留配置/结算复核信息。原有项目分摊、总账和银行义务继续使用实际行金额。
- E03 内部标准申报不能表达这些复杂税务/penalty/离职分类，因此阻止这类工资通过标准本地报表准备路径，须等待适配器字段映射及外部复核。不是生产 STP/ETP 或 SuperStream 认证。

公司以建材批发为主，岗位为财务、销售、库管。岗位名称不足以确定 Award、等级或企业协议；本阶段完成可配置规则与结算工作流，未配置的规则没有自动启用。**这不等于已实现澳大利亚全部法定权益及所有行业的自动判断。**

规则依据复核：[Fair Work final pay](https://www.fairwork.gov.au/ending-employment/final-pay)、[annual leave payment](https://www.fairwork.gov.au/leave/annual-leave/payment-for-annual-leave)、[ATO Schedule 7](https://www.ato.gov.au/law/view/pdf/ldt/op2016-005.pdf)。年假、loading 与 ETP/unused-leave 的税务类别需分别审核，本项目不把手填金额称为法定计算认证。

## S03 FIFO

入口 Inventory 的 Inventory costing policy。持有 inventory.cost.read 可查看，accounting.post 才能改策略。按用户确认，**所有仓点的数量和金额均为零后才能切换**；旧库存保持原成本法，历史出库及分录不重算。策略记录可信操作者、时间和原因，商品编辑保留该策略。

FIFO 以仓点/商品为单位，按实际持久化的收货过账顺序消耗成本层；FIFO 交易不能回填到已有更晚业务日期之前。每层保留剩余数量与精确货币金额，部分出库按比例取整，最后耗尽取走剩余分值，零成本层仍有效。显示的平均单价只是剩余库存总值/数量，不用来替代 FIFO 出库成本。

采购收货、期初导入、销售 dispatch、供应商退货均使用统一成本引擎。退货及出库撤销按冻结的原成本作为新入库层排到当前队尾，既不修改历史层，也不重新计算已过账 COGS。客户实物退货撤销定向移除该次退货层；层已耗用时阻止撤销，不能挪用其他层的数量/金额。

FIFO 层从现有不可变成本流水重建，不另存一份可漂移的层余额；恢复校验同时核对已耗尽历史层、当前层、库存金额、策略及策略审计。不接受没有零库存边界的历史重新计价。

## S04 客户 Notes

入口客户详情 Notes & Activity。便笺已从离页丢失的预览改为本地持久记录，随客户仓库进入主进程事务、备份、恢复和权限投影。读取要求 sales.read，新增还要求 contacts.write；审计员不能新增；页面入口继续沿用客户工作区权限。

便笺采用追加式历史，保存 note ID、operation ID、正文、可信作者、时间和来源；纠错另加一条并引用原 ID。Desktop 不能声明外部 ID。Sales import 必须提供来源 ID，相同 ID 和正文重试去重，跨客户或不同内容复用被拦截。导入是用户审核录入的来源记录，**没有虚构独立销售系统的联网同步或远端身份认证**。原有拜访、任务备注和账户交易活动各自保留。
