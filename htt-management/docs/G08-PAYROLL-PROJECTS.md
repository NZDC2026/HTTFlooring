# G08 工资工时项目维度

范围：在现有本地工资、项目报表及可信主进程架构内，为工资工时加入项目引用、历史快照及自动成本归属，不连接独立后台，不修改 AU 税务、净工资付款或外部申报规则。

## 工时与权限

Timesheets 增加 Project 选择与 Frozen project 列。未选择时为 Unallocated。项目必须存在且 Active，主进程还要求现有 payroll.manage 与 accounting.read；提交、批准沿用 payroll.manage／payroll.approve。不能从 renderer 注入项目名称、版本或操作者。

保存时冻结项目 ID、code、name、revision。后续项目主数据变化会阻止未经重新复核的工时批准／工资准备或批准／过账。需先取消尚未过账且占用工时的工资批次，再重新打开工时、保存当前项目复核、提交／批准并准备替代工资。已过账工时继续锁定，只有正规工资冲销才能释放。

同一员工、同一天、同一工资项可以按不同项目拆行；相同项目不能重复，同一员工当天全部项目和未分配工时合计仍不超过 24 小时。已有未分配工时保持原语义。

## 成本归属与冻结

时薪：按实际纳入工资的已批准工时对应 Earnings 费用金额归属项目，使用已冻结工资项和单价。未批准工时不计入；带薪休假与未分配工时保留为未分配成本。

薪资：Salary 费用按已批准且纳入本次工资的记录工时比例分配。分母包含所有这些工时及纳入工资的休假小时；未分配工时和休假比例保留为未分配。此比例不推断缺失工时，不自行增减工资；工资审核人必须先确认记录完整性及必要的 salary override。

雇主供款：按本次已归属工资费用占全部 Gross 的比例分摊；未归属的工资、Allowance 等比例继续未分配。Deduction、PAYG、净工资及其银行付款不增加项目费用。按整数分使用确定性余数分配，保留未分配权重，项目合计不能超过对应费用行。

工资快照保存全部用于分配的原批准工时、休假记录、项目版本与每条工资费用行的归属金额。工资详情、payslip、工资复核 CSV 和个人导出可检查冻结成本。后续员工、项目名称或状态变化不会重写这些值。

## 项目报表与冲销

项目盈利报表仅从已过账工资原 GL 行继承快照，不创建额外分录或第二份可变成本记录。费用在工资 payDate 统计；工资实际付款不再计成本。每条来源只形成一次成本，项目加未分配与 GL 对齐。

原工资冲销沿原费用行自动继承相反归属，使用冲销日期。单独查询原期间仍保留原成本；冲销期间显示负成本；合并期间抵销。替代工资按自己的冻结来源计一次，跨重启和重复请求不重复过账。历史交易明细与 CSV 使用快照项目名称；项目汇总标题和预算仍来自当前项目配置。

带自动归属的工资费用行不再出现在可手工分配列表；主进程也拒绝手动覆盖或再次分配。应通过原工资正规冲销、修正工时并重新准备纠正归属。该行剩余未分配值也由工资来源负责。没有项目快照的旧工资保留原有手工管理分配方式，不追溯猜测项目。

## 迁移、恢复与验收

业务快照升级至 schema 29。合法 schema 28 及更早数据迁移时不添加猜测项目、不重算历史工资或现有手工分配，并保留迁移前备份。带新项目证据的数据不能冒充旧 schema。

恢复检查项目历史版本、工时与项目绑定、冻结来源身份／员工／日期／批准状态、休假小时、成本重算、实际工资行及现有分录绑定；拒绝遗漏、损坏成本或与手工分配重复的证据。已冲销后工时可修正，历史工资仍使用冻结来源。失败回滚和持久化确认不确定时的重启重试沿用原主机原子命令。

新增 19 项真实主进程集成用例及 1 项页面／角色用例，覆盖时薪、薪资、供款、休假与未分配、整数分舍入、项目更名／停用、相同日多项目、角色权限、重复报告／付款去重、反向及替代工资、释放后修正工时、回滚、提交确认失败重试、旧版本迁移、损坏快照与同科目总额平衡但项目明细错位的拒绝。

原生 Electron 使用 `/private/tmp/htt-g08-native` 独立合成档案。工时表确认 Project A 4 小时、Project B 3 小时与未分配 1 小时，冻结版本 v1，另有休假 8 小时。工资详情展开冻结成本显示 A 工资 120.00＋供款 14.40、B 工资 90.00＋供款 10.80。项目盈利报表实际显示 A 134.40、B 100.80、未分配 302.40 AUD，合计与公司 GL 537.60 AUD 对齐；没有第二份费用。工时、工资明细与报表截图检查可读。

桌面检查仅导航、展开及运行只读报表，未点击工资过账／冲销／付款。实际 repositories 和 storage 与种子证据逐项完全一致；验收后关闭独立应用。所有写入、冲销和异常恢复由真实主进程集成测试验证，未使用真实业务档案。
