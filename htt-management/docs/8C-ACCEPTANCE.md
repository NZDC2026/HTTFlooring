# 8C 本地身份、权限与操作审计

基线：2026-10-15 已验收的 8B 源码（49 个测试文件、418 项测试）。

## 已实现

- Electron 主进程持有用户、会话、权限、业务仓库及权威业务数据；不使用独立后台。
- 渲染进程的业务写入通过受限 IPC 命令交给主进程执行，保留原有同步 Repository 调用与 Service 校验。直接调用底层内部仓库方法会被拒绝。
- IPC 只接受当前应用窗口的主 frame；阻止外部页面导航和新窗口。一个用户数据目录仅运行一个应用实例。
- 首次启动自行创建管理员，无默认密码。密码使用随机盐与 scrypt 保存；登录失败锁定、注销、30 分钟会话空闲上限与 8 小时绝对上限由主进程核验。
- 管理员可创建用户、配置七种角色和启停账号；阻止停用或降级最后一个管理员。用户可验证旧密码后修改自身密码并退出会话。
- 销售、采购、收货、付款、贷项、履约、银行、GL、恢复和联系人写入均有主进程命令权限。系统来源分录不能通过手工凭证入口伪造或单独冲销。
- 恢复操作使用主进程会话中的用户 ID，不信任界面传入的 operator/approver。
- 用户与审计数据采用原子文件替换和 fsync；业务命令先保存审计意图，再执行、持久化业务结果并确认审计。失败回滚业务内存；结果已提交但审计确认失败时阻止重复写入。
- 重启根据已保存的业务 command ID 判定未完成的审计意图是否提交；只补充审计结论，不重放业务操作。
- 审计包含时间、实际用户、操作、权限、对象、结果和命令 ID；API 不提供修改/删除审计功能。HMAC 链在启动时检查，记录中不保存密码。
- 界面提供登录、当前身份、注销、角色管理、审计过滤及分页；按角色控制工作区访问，主进程同时过滤返回的数据。

## 数据与首次使用

正常运行 `npm run dev` / `pnpm dev`，或打开构建后的桌面应用。
首次启动显示“Create the first administrator”，由使用者设置自己的用户名和密码（至少 12 个字符）。
通过 Settings → Manage local access & audit 管理用户和查询审计。

主进程数据目录：Electron userData 下的 `local-security/`：

- `security-v1.json`：本机用户与审计。
- `business-v1.json`：主进程权威业务仓库和持久化键。
- `legacy-profile-backup-v1.json`：首次迁移前该桌面 profile 的旧本地存储备份。

首次管理员登录会将当前桌面 profile 的旧本地数据导入主进程存储；先备份、后导入成功才更新界面缓存。已有主进程数据不会被随后登录时传入的渲染进程数据覆盖。
测试账号仅用于独立的 `/private/tmp/htt-8c-desktop-acceptance-profile`，不是正式应用的初始账号。

## 明确边界

这是单机桌面权限系统，不提供多电脑集中身份或共享数据库。
应用权限边界保护主进程免受渲染进程伪造身份与直接业务写入；拥有本机文件和进程控制权的操作系统管理员不在此权限隔离边界内。审计不是外部不可篡改存证服务。
8D 仍需专门完成全业务重启/故障恢复、完整 FIFO 验收、版本迁移和备份还原操作流程；当前不存在自动绕过核验的财务恢复功能。
