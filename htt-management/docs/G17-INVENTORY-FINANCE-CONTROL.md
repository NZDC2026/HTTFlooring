# G17 库存差异进入财务总控

完成日期：2026-10-23。范围是本地管理端库存控制集成，持久化结构仍为 31，不连接独立后台。

## 完成行为

`/accounting/finance-controls` 使用真实成本流水、科目和分录，按所选日期调用与库存对账和主进程关账相同的库存到 GL 计算。新增一个 Inventory 控制项，库存子账/GL/差额及通过状态共同进入控制总数、通过数、失败数和 overall status。真实差额时，即使其余控制通过，总控仍为 Review Required。

计算失败、控制科目缺失或不唯一、金额/数量非有限、重复成本 ID、库存站点/商品/基本单位失效、估值负数或单位冲突都不能变成通过。检查失败标记 unavailable，页面三项金额显示 Unavailable，保留原因；不把无法核实的金额展示为零差额已核对。完整性检查覆盖截止日前成本记录，含最终余额为零的记录；无法识别日期的记录无法可靠归属，保持失败。

库存审查链接带 `asOf=YYYY-MM-DD`，审查页与总控使用同一个日期。两页从 URL 读取日期，改变日期更新导航状态；无效链接日期有明确提示并回退到当前业务日期。库存审查失败显示可读的日期/原因和返回财务总控的入口，不抛成空白页。日期不会触发后台写账。

总控没有新增平衡分录、自动调整、修复或关账捷径。主进程继续独立运行 periodCloseChecks，金额不平产生 INVENTORY_DIFFERENCE，计算/完整性失败产生 INVENTORY_CHECK_FAILED，两者都带相同截止日的审查路径，并阻止 close。失败关闭保持业务文件及期间状态，审计记录失败；正常数据重启后仍可正常关账。

现有读取权限保持：财务总控 accounting.read，库存对账 inventory.cost.read；当前可读总控的管理/财务/审计角色均有库存成本读取权限。销售/仓库/采购角色不能通过链接取得财务成本读取权限。成本流水使用现有 Repository 订阅，成本、分录、科目或日期变化会重新计算；没有默认为空库存账的兼容绕过。
