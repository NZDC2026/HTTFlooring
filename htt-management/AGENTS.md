# HTT Management project instructions

When adding or changing a user-facing feature, include a clearly labelled sample preview that demonstrates the populated result. For workflows, cover the meaningful states, such as pending and completed, and explain where to see the sample in the delivery notes. Use realistic synthetic values in a read-only preview or isolated test workspace. Keep sample records out of live financial, payroll, inventory, and notification workflows unless the user explicitly requests a specific write. Preserve existing sample coverage when editing a feature.

After completing an application change, run the relevant checks and production web build, then automatically restart the online web service and verify public availability. The user has authorized these restarts. Preserve the existing data directory and deployment settings. Report any failed deployment or verification. Documentation-only changes do not require a restart.

## Desktop responsive design standard

Use the light workspace theme: sidebar #F3F5F7, selected navigation #E1F5E9, primary #087F5B, page #F8FAFB, cards #FFFFFF, text #182230 and border #E5E9ED. All future user-facing development must automatically support 24-inch and 32-inch desktop setups using available CSS viewport width. Use the same font sizes, controls, row heights and component dimensions at 1920×1080 and 2560×1440; do not enlarge typography or components with viewport width. Use the additional width for more columns/content per row and flexible layouts. Follow src/layouts/light-workspace-theme.css, src/layouts/workspace-components.css and existing feature styles. Use shared data-ui primitives for new buttons, fields, cards and badges; dialogs rendered outside main must use the same screen-only theme. Keep related labels, badges and totals consistent, avoid unintended maximum-width gaps, and confine horizontal scrolling to wide tables. Validate both desktop sizes with populated Sample states. Preserve mobile and print layouts.
