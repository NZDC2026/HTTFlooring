# 阶段C：直接法现金流量表、分类与银行/总账核对

本批仅修改 htt-backend；新增036迁移，001—035不变。提供基础直接法现金流 API、可审计分类及核对，不运行生产迁移，不修改三个客户端。

## 日期、金额与报表

GET `/api/v1/accounting/reports/cash-flow?from=2026-10-01&to=2026-11-01&page=1&pageSize=25`。

日期按已过账 journal_entries.posting_date，半开区间 `[from,to)`，1—366天。AUD金额为精确十进制字符串。经营 OPERATING、投资 INVESTING、筹资 FINANCING 分别返回流入、流出、净额；INTERNAL内部划转单列、净额应为零；UNCLASSIFIED待分类单列，不隐藏于三类活动。即使待分类流入/流出净额为零，只要有待分类金额，分类仍不完整。明细默认25、最大100条，总计覆盖全部结果，不随分页缩减。

报表包含：期初现金、期末现金、现金净变动、三类活动净额、待分类净额/数量、内部划转净额、总账差额、现金范围差额；各银行账户的期初/期末、范围、活动状态和最近对账快照；分页分录来源、资金方向、分类依据、版本及原单据ID。明细的 `signedAmount` 是总账资金变动；展示流入/流出应使用 `inflowContribution/outflowContribution` 及 `isReversal`，不能把正的冲销分录直接当成真实回款。

- `ledgerStatus` 核对总账：期初 + 三类活动 + 待分类 + 内部净额 = 期末；现金期末 = 全部BANK控制科目期末 − 范围外BANK期末；同时校验每条现金分录完整分配、内部划转净额为零及范围记录完整。
- `classificationStatus` 仅在没有待分类、覆盖差异和待确认迁移范围时为 COMPLETE。
- `bankStatus` 复用有效银行对账：当前历史总账 − 未达存款 + 未达付款 = 银行期末，并与原对账账面快照比较。只有各已用银行的有效对账均覆盖 `to-1` 才为 RECONCILED；无记录为 NOT_AVAILABLE，缺少银行或截止日覆盖为 PARTIAL，差额为 UNRECONCILED。现金柜不冒充银行已对账。
- 总状态 READY 表示账面现金流计算与分类完整；银行覆盖状态必须单独查看。待分类/范围待确认为 INCOMPLETE，真实核对差异为 UNRECONCILED。READY 不代表已连接网银或所有外部流水已核实。

银行流水导入、匹配和完成对账本身不产生现金流；现金流只来自实际总账现金分录。发票、应付账单、库存成本、GST重分类、预收预付核销、贷项抵扣等非现金事项不会重复进入本表。

## 默认分类与人工拆分

已验证原始业务记录及对应过账类型的客户收款、贸易供应商付款、客户退款、供应商退款默认经营活动，含业务预收预付。默认是本项目贸易业务口径，不表示任意预付款均属经营；购买长期资产等必须由财务按真实用途覆盖分类。手工分录不按科目名称、ASSET/LIABILITY/EQUITY类型猜测用途，列待分类。

纯现金及现金等价物账户之间、无非现金对方分录的划转自动 INTERNAL，不能人工改为外部经营/投资/筹资活动来放大流入流出。混合划转与手续费需要人工拆分，内部部分各现金腿合计严格为零，手续费另列；同一张凭证的每一条现金腿都必须完整覆盖，分配绝对金额为正且不能超额。借款本金/利息、投资本金/可收回GST等可在同一现金腿拆分。

同原分录的收付款/退款撤销继承原现金分类，并冲减原流入或原流出，不把记账撤销伪装成反向真实收付款；跨期只含冲销时允许原方向为负。真实客户/供应商退款仍按实际资金方向列示。禁止独立改写冲销分类；修改原分类后，原款与撤销同时采用新版本。重付或退款更正属于新的资金事实；如果任一前序资金当前采用人工分类，新资金自动进入待复核，不能擅自恢复经营默认；确认新用途后可单独分类。金额、资金账户和GST账不因报表分类改变。

参考[AASB 107](https://standards.aasb.gov.au/sites/default/files/2026-03/AASB107_08-15_COMPsep24_01-26.pdf)的三类活动、直接法及现金内部移动口径。澳洲投资/筹资现金流中可收回或应付税务机关的GST部分应列经营，见[Interpretation 1031 第10—11段](https://standards.aasb.gov.au/int-1031-may-2019)。API允许明确拆分；财务须依据原票据、可收回性和适用口径输入，系统不凭银行净额猜测税额，不另造GST归属或BAS申报。利息、股利和特殊交易同样需财务按适用政策分类，不硬编码未来准则政策。

## 现金范围与旧数据升级

范围由 accounting.cash_flow_scopes 明确保存，不随账户停用丢失历史。初始 BANK、CASH、LEGACY纳入；CARD_CLEARING排除。新账户首次过账前可由财务配置；确认且已经使用后不能切换纳入/排除或重新标为待审，避免历史现金流被静默改写。改变后续用途需新账户。银行目录更新也不能绕过此规则；账户并行过账与范围修改使用行锁串行化。

升级时已有现金分录的账户标记 `reviewRequired=true`，报表 INCOMPLETE。先在范围接口确认纳入/排除及原因；该首次确认允许修正旧默认且不改动旧GL。确认后范围锁定，才能进行相关人工分类。未使用旧账户可按普通新账户配置。新公司默认银行及新账户使用上述初始口径，正式过账前应完成银行设置。

## 维护 API 与权限

所有路径加 `/api/v1`：

| 方法/路径 | 用途 |
|---|---|
| GET `/accounting/cash-flow/scopes` | 范围、版本、待确认和锁定状态 |
| PUT `/accounting/cash-flow/scopes/{bankId}` | `{included:true/false,reason}`，需当前版本 If-Match |
| GET `/accounting/cash-flow/journals/{journalId}` | 当前分类及不可变版本历史 |
| PUT `/accounting/cash-flow/journals/{journalId}/classification` | `{mode:"CUSTOM",reason,allocations:[{journalLineId,category,amount}]}` |

分类使用该凭证当前 `revision` 作为 If-Match；尚无人工版本时为0。AUTO模式必须无分配，追加一版恢复默认/待分类；CUSTOM最多100条，现金腿/类别不得重复。历史版本保留原原因、分配、时间和操作人。版本记录不受会计期间关账/银行对账影响，因为它不改写财务事实；正式归档报表应另外保留输出及版本。

查询需同时具备 `accounting.reports.read`、`accounting.ledger.read`、`accounting.banks.read`。分类新增 `accounting.cash_flow.classify`，范围维护新增 `accounting.cash_flow.configure`；ADMIN/FINANCE默认授予。其他角色不能借维护接口读取余额，跨公司ID不可访问。写操作还需 Idempotency-Key，缓存重放仍重新授权；同键重放只产生一次事实，不同请求争抢同一版本只有一个成功。审计、Outbox、幂等和分类/范围同事务，失败整体回滚。

三张新增表强制公司RLS，分类头和分配不可变，应用角色不能直接DML。受限definer函数加权限、范围及来源验证，延迟约束验证分配完整性和内部划转。各响应使用单条SQL快照，凭证过账和分类提交只能整笔可见。现金及分类视图通过物化CTE避免重复展开，保留现有查询超时限制。多次独立请求的 snapshotAt 不相同，不承诺跨请求共同快照。

## 本批边界

本批为单公司AUD基础直接法报表；未新增固定资产、借款合同、现金等价物估值或合并模块。不能仅凭银行账户类别认证投资是否符合现金等价物定义。未含间接法、外币汇兑、合并抵销、现金柜实盘、法定报表模板、PDF/Excel导出、永久归档、真实银行feed及BAS申报。分类与范围在上述明确规则下配置，正式账务仍走现有合法过账/冲销流程。整个阶段C及生产部署验收不因本批自动完成。
