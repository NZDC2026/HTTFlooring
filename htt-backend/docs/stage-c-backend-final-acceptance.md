## 库存、往来、总账、GST及银行一致性

新增加现金制与非现金制两条串联验收：有估值库存开单→拣货/发运/COGS→销售发票→客户收款及同键重放→供应商费用账单/进项分类/付款→独立批准的佣金计提/清算关联→真实来源现金分录与流水匹配/对账→Full BAS及工作台。

样例为测试数据：库存初值100，供货成本30，净销售300、GST30，费用100、进项GST10，佣金30；收款330、付款110，指定银行余额220，未结AR/AP均0，净利润140，库存剩余15.4基础单位。核对库存/控制科目、信用、激励负债与GL、BAS 1A=30/1B=10/netGST=20、现金流/银行及BS差额为0。清算转移不伪装成银行工资付款。每个重要过账点调用原财务/对账检查；数据不会用补平分录掩盖不一致。

同时验证：非零激励草稿出现在关账预检阻断项，独立审批后该项消失；当前会计期未结束时仍保留合法的 PERIOD_NOT_ENDED 阻断，不以测试直接宣布当前期间已关账。已关闭期间/年结/重开等合法路径由原75项关账专项独立覆盖。

## 可复现验证

配置四个专用 HTT_TEST_*_CONNECTION（数据库名称含test），使用.NET10和PostgreSQL17，运行 `sh scripts/verify.sh`。脚本锁定依赖、构建Release、验证单元测试，并以短批次完整执行发现的集成测试；结果写入单独目录，任何异常非零退出。

并行CI可使用 `verify-batches.py --shard-count N --shard-index I`，每个实例必须配独立测试库；只有所有分组清单并集精确等于完整发现清单且每组全部通过，才可报告全量通过。本次补充新串联2项；重复运行与平台数量不相加充当更多用例。详细平台、构建、源摘要及实际结果在[verification.md](verification.md)本轮记录和机器可读验收清单中。
